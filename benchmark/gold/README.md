# IERB-P gold set format

Both files are regenerated by `../generate.sh` and are deterministic at seed
4471. Licence CC BY 4.0.

## identities.csv

The gold partition. One row per accused row in the corpus. This is the complete
answer and it is what `score.py` reads.

| Column | Type | Meaning |
|---|---|---|
| `AccusedMasterID` | string | Primary key of the `Accused` row in `corpus/Accused.csv` |
| `GoldPersonID` | string | The person who committed the offence, `P000001` form |

7,611 rows on the default task, covering 3,840 distinct people and 10,503 true
matching pairs.

`GoldPersonID` values are arbitrary labels. Only the partition they induce is
meaningful, so a submission using entirely different identifiers scores
identically.

## pairs.csv

A labelled pair sample, for methods that train on pairs rather than on a
partition. Not used by the scorer.

| Column | Type | Meaning |
|---|---|---|
| `AccusedMasterID_A` | string | First row of the pair |
| `AccusedMasterID_B` | string | Second row |
| `label` | 0 or 1 | 1 when both rows carry the same `GoldPersonID` |
| `stratum` | string | `positive`, `hard_negative` or `easy_negative` |

Every positive pair is included, 10,503 of them. Negatives are sampled in two
strata rather than uniformly, because a uniform sample from the 29 million
possible pairs is almost entirely trivial and teaches a model nothing.

**hard_negative**, 40,000 pairs. Two rows that share a crude name token but are
different people. This stratum contains the planted collisions, groups of two or
three genuinely different people forced onto an identical name in an identical
district. Ten of them additionally share a `CaseMasterID`, which makes them
provably different people from the schema alone.

**easy_negative**, 10,000 pairs. Two rows sharing no name token at all.

The stratification means the negative sample is not representative of the
corpus. A model calibrated on `pairs.csv` will be miscalibrated on the full
corpus, and any probability it emits should be recalibrated against a
representative sample before it is trusted. `score.py` is unaffected, since it
works from `identities.csv` over every pair.

## What is deliberately absent

There is no validation split. The corpus is generated, so a second corpus at a
different seed is one command away and is a better held out set than a slice of
this one.

```
python -m data.generator.generate --cases 5000 --seed 9137 --out held_out
python benchmark/make_gold.py --corpus held_out --out held_out_gold
```

Reporting on a second seed is not required. It is the fastest way to show a
method has not been fitted to this particular corpus.
